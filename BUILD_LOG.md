## Key decisions (ADRs)

**ADR-001 — Rust instead of C++/D3D11.** The build sandbox is Linux with no MSVC, no
Windows SDK and no GPU. `PLAN.md` §3 explicitly names Rust + `egui` + `wgpu` as an
approved alternative with identical architecture. Stakeholder confirmed this choice.
The Windows-native path is preserved as a port target: module boundaries in
`crates/astro` and `crates/core` are platform-free by design.

**ADR-002 — 3D scene rendered via egui painter, not raw wgpu pipelines.** egui already
owns the framebuffer; drawing the scene as painter primitives (line strips for orbits,
shaded circles for bodies, additive dots for belts/starfield) gives the exact 1px
flat HMI look of the reference image with no shader code, and works on the software
rasteriser used for headless verification. Depth sorting is painter's-algorithm on
view-space Z. If perf targets (§12) are missed at 20k belt points, the fallback is a
single `wgpu` instanced-point pass behind the same `Scene` trait.

**ADR-003 — Ephemeris fidelity (stakeholder-confirmed).** Truncated VSOP87D for the
8 planets + Pluto (target <1″ against Horizons over ±century), Kepler osculating
elements + secular rates for moons / asteroids / comets / exoplanets. Accuracy
ceiling is stated in the UI footer per §5.2.

## Session 5 — probes, sky sphere, density, legend + the two user-reported bugs

### User request 1: "the animation slows down when a planet is selected"
Root cause (measured): with a selection the SCOPE cell re-baked 121 samples via
full `resolve()` (≈15 full-series VSOP87 evaluations each) every time sim-time
crossed `period/240` — at 1 yr/s that is ~127 re-bakes/second. The frame loop
clamps `dt` at 0.1 s, so the fps collapse literally slowed simulated time.
Fixes: (a) `telemetry::sample_plot()` — position-only sampler (1 VSOP eval per
sample for planets; moons use their exact mean-circle radius; small bodies /
probes use Kepler); (b) window quantised `period/64`; (c) re-bakes wall-clock
throttled to ≤ ~7/s (`ScopeCache::baked`); (d) `telemetry_planet()` now evaluates
VSOP for (planet, Earth) once — 15 → 6 evaluations/frame; (e) per-frame
allocations hoisted (`small_bodies()`, `moon_defs()` are `OnceLock` statics);
(f) the selected small-body orbit loop is cached in `SceneCache::sel_orbit`
(osculating = static curve); (g) frame `dt` clamp relaxed 0.1 → 0.25 s so a
hitch can never halve the sim rate again. Verified at 1 yr/s + MARS selected:
scope trace correct, fps at cap.

### User request 2: "zoomed in on a planet, free-orbit → camera jumps to Sol"
Two compounding causes: (a) TOP-DOWN pins `cam_focus` to the origin every
frame, so ENTERING FREE lerped the orbit centre from Sol across the system at
planetary zoom; (b) an orbit drag that released inside the scene widget could
count as a click on empty space → deselect → FREE target = origin. Fixes:
FREE snaps `cam_focus` to the current target on mode entry (fly-to remains for
target changes *within* FREE); selection is only cleared on a genuine click
(pointer moved ≤ 4 px between press and release, `SceneCache`-independent
`st.click_origin`), in both scenes.

## Session 7 — 5th spectra graph: MIR fingerprint region + class MATCH

* USER REQUEST: "a 5th graph, more complex than the others, that works like a
  fingerprint". Chosen design: the MIR **fingerprint region** — in spectroscopy
  4000–400 cm⁻¹ (2.5–25 µm) is literally the fingerprint region, where every
  solid-state vibrational mode leaves a narrow band, so the pattern identifies
  composition the way a fingerprint identifies a person.
* `spectra.rs`: `fingerprint()` builds an `FpCurve` per body — normalised
  emissivity on a 260-sample wavenumber grid (FP_MIN 400 … FP_MAX 4000 cm⁻¹),
  assembled multiplicatively from 17 material feature sets with published band
  centres (H2O ice 3150/1645/800/620, CO2 2340/667, CO 2138, CH4 3010/1304,
  NH3 3370/1070, N2 2328, SO2 1345/1150, SO4 1120/640, CO3 1430/880/712,
  Si-O stretch 1030 + bend 550/470, olivine 880/985, pyroxene 920/1050,
  plagioclase 1080/580, phyllosilicates 3680/3420/1020/950, aliphatic C-H
  2955/2920/2860 + PAH 3050/1610/1300/1160/885, O3 1045, H2SO4 1180/900).
  Same honest-models rule as session 6: every curve states its model class.
  Feature sets picked per body exactly like the other graphs — name tables for
  planets/moons, keyword parsing of the composition string otherwise, SBDB
  taxonomic letter for asteroids (M-types get a featureless low-emissivity
  baseline). Stars/probes/unknowns: flat curve, match disabled.
* MATCH score: 14 class archetypes (S/C/V/M-type, H2O-ice world, cometary mix,
  tholin, CO2/SO2 atm, TNO ice, Io SO2, gas giant, ice/rock moon, ocean world,
  lunar plagioclase rock) compared by Pearson correlation of the curves;
  featureless curves only match the featureless metal archetype. Archetype
  curves cached in a `OnceLock` (full_spectra runs per frame).
* `layout.rs`: `fp_graph()` renderer — FTIR convention with the wavenumber axis
  REVERSED (4000 cm⁻¹ left → 400 right) plus a µm sub-scale row, pink trace
  (255,120,220), six deepest-feature tick labels staggered, model note in the
  plot corner, green/amber MATCH readout (own line when the column is narrow).
  Graph takes the FULL column width below the 2×2 grid: it carries far more
  features than the other four and needs the room.
* Bugs caught by the verification pass: `"BASALT".contains("SALT")` was giving
  the Moon sulfate bands (salt keyword now matches the plural "SALTS"); the
  first archetype library had no gas-giant/ocean/ice-rock/lunar classes, which
  mislabelled Jupiter (49% cometary) and Luna (90% Io-like). Both fixed;
  verified via a throwaway print test: Luna→PLAGIOCLASE 100%, Venus→CO2/SO2
  80%, Earth→OCEAN 100%, Jupiter→GAS GIANT 100%, Halley→COMETARY 99%,
  Vesta→V-TYPE 100%, Psyche→M-TYPE 100%, Bennu→C-TYPE 92%, Eros→S-TYPE 100%.
* Tests: `fingerprint_region_graph_is_consistent` (grid span, normalisation,
  feature-in-range, dips present, ice-moon correlation ≥55%, metal exact match,
  stars/probes unmatched, ice-vs-sulfur moon curves differ). 9 app + 26 astro
  tests green.
* Shots: S7_fingerprint_europa / _halley / _luna / _mars (four visibly
  different fingerprints); shots.sh gained the session-7 block.
